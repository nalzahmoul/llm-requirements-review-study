Codebook: Ask or Assume? (MO2RE 2027)

Both authors code all 33 responses independently with this codebook. It is generated from runner/study.py; change rules only there.

1. What you code

For each response you have the interview transcript (coding/transcripts), the 12 predefined requirements of the Ski scenario, and the response (coding/blinded_responses/RSPxxx.txt). Code every predefined requirement once per response, then list the response's extras.

2. The five codes

CodeDefinitionRule
SupportsThe LLM states the requirement using only information provided or clearly confirmed by the stakeholder.Information counts as provided if the stakeholder stated it or clearly agreed when the interviewer raised it. A general 'yes' to the interviewer's closing summary does not confirm details the stakeholder never mentioned. Rewording is fine as long as no new detail is added.
AsksThe LLM requests clarification or identifies missing information without supplying it.A question that offers options (e.g. 'email or upload?') is still Asks. A statement such as 'the deadline was not specified' also counts.
Assumes explicitlyThe LLM introduces unsupported information but marks it as an assumption or as requiring confirmation.E.g. under an 'Assumptions' heading, 'we assume ...', '(to be confirmed)'. It supplies content, so it is not Asks.
Assumes implicitlyThe LLM presents unsupported information as an established requirement without indicating uncertainty.E.g. the stakeholder wants appointment cancellation but gives no deadline, and the response states a 24-hour deadline. Added details count here even when the rest of the requirement is supported.
OmitsThe LLM neither addresses the requirement nor asks for clarification about it.Leave the evidence empty.

3. Special cases

CaseWhenRule
Several codes applyDifferent parts of the response treat the same requirement differently.Take the first that applies: Assumes implicitly, Assumes explicitly, Asks, Supports, Omits. This captures unsupported information even when the response also gives supported content or asks.
Where to lookThe whole response counts: the requirement list, notes, assumptions and open questions.If one requirement is spread over several statements, judge them together.
ExtrasRequirement statements in the response that match none of the 12 predefined requirements.Check each against the transcript: Supported if its content comes from the transcript, Unsupported if not (e.g. an invented quantity, actor, integration, technology or policy). List each distinct one once per response. Leave out duplicates and clarification questions.

4. What to fill in for each requirement

  • code: Choose Supports, Asks, Assumes explicitly, Assumes implicitly or Omits (see the Codebook).
  • evidence: Copy the words of the response that justify the code (leave empty for Omits). For the two Assumes codes, the evidence must show the unsupported detail.

5. Once per response: extras

For every response, list each extra on its own row of the Extras sheet: the response ID, the statement (copy it or its first words), and Supported or Unsupported. Then write Y in 'extras_checked' on the Responses sheet, also when a response has no extras.

6. Blinding

Code alone. Until both sheets are complete, do not open the coding_key folder, data/cases.csv, data/all_cases.csv, the responses folder or the other author's sheet.
